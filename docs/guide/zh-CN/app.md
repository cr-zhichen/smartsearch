# App 配置与使用

## 安装和打开

在[发行页](https://github.com/konbakuyomu/smartsearch/releases/latest)下载适合系统与架构的安装包。Windows 安装到当前用户目录。App 自带运行环境，使用 App 不需要先安装 Python、Node.js 或独立 CLI。

本手册对应当前源码。环境准备和完整 App/CLI 语言切换属于开发版功能，稳定版 v0.1.20 尚不包含，下载时请核对发行说明。桌面包未签名；macOS、Windows ARM64、干净机器安装和完整 DPI 矩阵尚未全部完成实机验收。

从开始菜单或“应用程序”打开 **Smart Search**。已有配置会被复用；“概览”会提示主搜索、文档检索或网页读取能力是否缺失。

## 配置服务

1. 打开“服务商”，为缺少的能力选择服务。页面提供官方说明和申请 Key 的入口，具体选择见[服务商与配置](configuration.md)。
2. 填入服务商提供的地址、API Key 和模型。可选项先用默认值；服务商有具体要求再调整。
3. 需要检查连接时测试草稿，再预览并保存改动。测试和搜索可能消耗服务商的付费额度；打开 App 不会自动执行它们。

编辑内容在保存前都是草稿。密钥框留空或删空表示保留已保存的 Key；要删除它，须明确勾选清除。被环境变量覆盖的字段会显示有效来源，保存不会覆盖环境变量。正在运行的任务继续使用启动时的配置。

## 接入 AI 工具

1. 打开“AI 接入”，勾选已经安装且希望接入的 Codex 或 Claude Code。
2. 点击“检测环境”。检测只读取本地状态；核对清单后，再点击“安装缺少的组件”。
3. 查看执行进度。健康的 Node.js、Python 和独立 Smart Search CLI 会被复用，缺项安装在用户可写且独立于 App 的目录。无需先装 mise；App 不负责安装 AI 软件或代登录。
4. 点击“验证可用性”。如果 CLI 能启动但搜索配置缺失，去配置服务商；重装运行环境不会补上 API Key。
5. 复制 AI 测试指引，关闭 Smart Search，再粘贴到 AI 的新对话。首次只让 AI 调用独立 CLI 查看版本，不联网搜索；之后可自行试一次搜索，检查服务商连接。

页面分别报告运行环境、CLI 启动和接入文件的状态，也提示是否需要重启，以及 AI 实际调用是否仍待验证。接入文件就绪不能证明 AI 已加载它。出现提示后重新打开原先的 AI 或终端，App 不会强制终止它们。WSL 和远程主机需要分别配置。

已有接入文件内容不同时会被保留。先查看差异，再决定是否替换；明确替换会保留可恢复副本，额外文件不删除。Codex 使用 `~/.agents/skills/smart-search-cli`，历史 `.codex/skills` 副本会被提示并保留；Claude Code 使用 `~/.claude/skills/smart-search-cli`。其他已有安装目标仍可通过 [CLI](cli.md) 使用。

安装失败会显示对应步骤和恢复方法。重新检测后只补缺项。正在写入安装文件时，等待完成再升级、重新连接或退出。本地检查和版本验证不会发起付费 AI 请求。

## 平时使用哪些页面

| 页面 | 用途 |
| --- | --- |
| 概览 | 查看缺少的能力和下一步配置 |
| 服务商 | 编辑、测试草稿，预览后保存 |
| 搜索与研究 | 搜索、读网页、查站点地图和文档；生成离线计划或在线研究；复制和导出结果 |
| 活动 | 查看实际阶段、服务商、模型和耗时；取消本 App 启动的任务 |
| AI 接入 | 检测并准备独立 CLI，安装所选接入文件，验证本地状态 |
| 设置与关于 | 切换配置目录、添加活动观察目录、设置主题和语言，重置健康状态并检查更新 |

重要结论还要核对来源。搜索命中或摘要只是候选来源，不表示已经读取网页正文，详见[搜索、研究与证据](research.md)。

## 切换语言

在“设置与关于 → 语言”选择自动、简体中文或 English。自动模式在中文系统上使用简体中文，其他系统使用英文；选择保存在这个 App 中。切换保留未保存的服务商草稿和正在运行的搜索；受保护的安装或更新写入需要先完成。

独立 CLI 单独保存语言偏好。App 的选择不会改变终端偏好、服务商配置、AI 语言，也不改查询、回答或网页原文。第三方安装日志可能仍保留原语言。

手工测试时，先切英文并查看各页，再切中文并重启 App。确认选择保留、草稿没有丢失，最小窗口里的按钮能正常换行，键盘能到达主要操作。再试一个无效的本地设置，检查错误提示；这些检查无需付费请求。

## App 与 CLI 如何独立运行

App 的私有引擎支撑 App 自己的功能。独立 npm CLI 单独运行，关闭或卸载 App 后仍可使用。App 升级不替换独立 CLI，CLI 更新继续使用原安装管理器。

两者选择同一配置目录后可以共享服务商设置。Windows 默认路径是 `%LOCALAPPDATA%\smart-search`，也支持旧的 home 目录路径；可用 `SMART_SEARCH_CONFIG_DIR` 或 App 的目录选择隔离配置。不同进程继承的环境变量不同，实际生效的设置也可能不同。

App 私有引擎的绝对路径也能在关闭窗口后调用，但卸载 App 会移除它。长期 AI 接入应使用独立 CLI。外部活动记录需要 CLI 0.1.19 或更新版本；旧 CLI 仍能使用，只是不产生这些活动事件。

## 活动、更新和卸载

活动每两秒刷新，只观察当前或明确添加的目录。默认记录元数据，不保存查询、回答、请求头或 Key。已结束记录默认最多保留 7 天 / 1000 条；清除活动不删除配置、研究证据或导出结果。心跳过期表示状态未更新，不代表执行成功。

存在 App 任务时关闭窗口，可以选择后台继续、取消 App 任务并退出或返回。后台窗口可从通知区域恢复，再次启动也会唤起同一窗口。App 不会取消终端或 AI 独立启动的 CLI 任务。

使用更新页，或从发行页下载新安装器。完成受保护的写入并关闭 App 后再替换文件；Windows 安装器发现 App 仍在运行时会拒绝覆盖私有资源。卸载保留共享配置、独立 CLI 数据、研究证据和导出结果。

构建与协议说明见 [desktop README](../../../desktop/README.md) 和[桌面协议](../../../desktop/PROTOCOL.md)。遇到问题可查[排障](troubleshooting.md)。
