# npm 自带运行时版本验证

构建源码与安装的 Python 元数据允许符合 Python 版本规范的等价表示。构建时使用现有 packaging 版本解析器，比较完整版本的含义；不截断为主次补丁版本，不把预发布当成稳定版。真正不同或非法的版本继续在启动 PyInstaller 前失败。

### Scenario: 等价版本可以继续构建

WHEN 源码为稳定版本或 alpha/beta/rc/dev 预发布，安装元数据仅经过 PEP 440 规范化，例如 0.1.24-beta.2 对应 0.1.24b2，THEN 不误报元数据陈旧，继续进入同一构建流程。

### Scenario: 真正错误的安装版本仍被拒绝

WHEN 源码与安装元数据的补丁版本、预发布阶段或预发布序号不同，或输入非法，THEN 在创建发布产物前失败；不得关闭元数据保护或只比较数字前缀。

### Scenario: beta 分发保留公开版本并通过实际流程

WHEN 修复后的源码执行既有 beta/next 发布，THEN 冻结 CLI 的版本与 npm 原始 SemVer 一致，真实 tarball 安装及六平台构建/运行时隔离检查通过，平台包先于主包发布，主包 next 可读回；latest 保持原稳定版本。若外部发布权限缺失，明确记为阻塞而不是成功；不替换个人环境。
