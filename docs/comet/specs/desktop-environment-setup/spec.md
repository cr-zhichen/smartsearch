# App 环境准备、双语使用指南与语言切换

## 1. 环境检测

App 能在外部 Node、Python 和 CLI 全部缺失时启动环境管理界面。检测当前平台/架构、实际可执行的 Node/npm、能创建 venv 并使用 pip 的受支持 Python、Smart Search CLI 的来源与运行状态，以及本机当前用户环境中的 Codex/Claude Code 和接入文件。检测只读，使用有超时的已识别可执行程序和固定参数；不运行会自动安装依赖的 CLI wrapper，不把磁盘残留目录等同已安装可运行的软件。

每项显示“可用、缺失、需要处理、检查失败/无法确认”及下一步。高级详情提供路径、版本、来源和检查时间。发现不了不等于用户电脑任何位置都没有；WSL/远程环境不自动探测配置，也不能被本机通过状态覆盖。

### Scenario: 检测准确且无安装副作用

在无环境、兼容版本、过旧版本、失效命令、Python 不支持 venv/pip、CLI 运行时缺损和检查超时的输入下，状态与后续动作准确；仅有 AI 配置目录不显示 AI 本体已可用。连续检测不下载、不创建 CLI 私有运行时、不安装技能、不修改 PATH 或配置。

## 2. 独立环境安装

用户点击“安装缺少的组件”后，按检测计划补齐运行环境、独立 CLI 和所选 AI 接入文件。健康兼容项直接复用；缺失的运行环境使用受支持稳定发行版，npm CLI 使用读取后锁定的稳定版本。Node/npm 和 Python 不要求用户先理解或手动安装 mise。

新安装由当前用户拥有，位于 App 程序目录之外；CLI 的 Python 环境有完整 venv/pip 支持。App 可使用自身后端完成管理，但外部调用入口不得转向 App 内置二进制。关闭或卸载 App 不删除新环境、CLI、接入文件和共享配置。

Node 使用官方稳定 LTS 分发，缺少 Python 时采用用户目录内受控安装的 Astral CPython，允许以校验过的 uv 作为内部安装辅助。界面详情标明真实来源，不要求用户安装系统级 Python 或理解 uv；不使用缺少现有安装合同所需 pip 的 Windows embedded ZIP。

### Scenario: 干净环境可准备独立 CLI

隔离且最初没有 Node/npm、Python、Smart Search CLI 的环境中，用户一次确认安装计划后完成依赖与 npm CLI 安装。实际启动链使用独立目录中的组件，读回正确 CLI 版本；App 程序目录不可用时独立 CLI 仍可运行。重复安装不重复下载或制造同名副本，已验证组件保持可复用。

## 3. 现有安装与来源

复用现有健康环境，保持明确 npm/mise 安装的所有权和升级方式。“准备环境”不顺便升级所有已安装工具；独立 CLI 的显式升级复用当前更新流程。项目级、多个冲突来源、未知来源、锁定版本或无写权限时，展示具体问题和可执行处理说明，不自行提权、更换全局默认或覆盖命令。

由本功能创建的用户级 npm 安装必须能在后续检测和更新中重新识别，App 重装后不能误判为另一种来源。安装开始前重新核对计划中的路径和来源，期间发生变化时重新检测。

### Scenario: 复用已有安装且保护来源

普通 npm、全局 mise、本功能拥有的用户目录、项目锁定和多来源冲突分别得到正确计划；健康项不重装，更新只针对 Smart Search 并使用原管理器。未知来源、权限不足或计划后来源变化不会被强改，也不会通过另建副本伪装解决。原环境和其他命令保持可用。

## 4. 下载、安装与失败恢复

运行环境只从明确配置的可信上游以 HTTPS 下载，绑定确切版本、平台架构、大小和可核验摘要；npm 包沿用 npm 的包完整性验证。下载与解压不接受任意 URL、越界归档路径或网络返回的执行命令，校验失败不得执行或报告已安装。运行环境的来源和校验方式在详情可见，摘要校验不等同代码签名。

显示真实阶段和下载字节；能够安全取消的下载可以取消，包管理器正在写入时不承诺强制取消或自动回滚。失败后保留已成功组件与可诊断信息，重新检测再补缺；不得清理与本安装无关的目录。安装日志有上限并脱敏，用户提供的 Key 不传给安装子进程。

### Scenario: 安装失败不会产生虚假成功或破坏原环境

网络中断、摘要/大小不匹配、错误架构、越界归档、无写权限和 npm/Python 安装非零退出均停止依赖步骤并显示原因；错误包不能执行。重试复用已成功组件，日志不含合成密钥；未完成临时内容不会被当作可用安装。

## 5. 外部命令可达性

准备过程让目标 AI 能通过稳定入口调用独立 CLI。Windows 只修改本功能拥有的当前用户 PATH 项；macOS 的接入同样不能假定 Finder 启动的 App 与交互式 shell 拥有相同 PATH。必要时接入文件提供已经验证的独立 CLI 绝对路径，路径有空格和中文时仍可用。

新进程的命令解析要读回验证；已打开的终端或 AI 可能持有旧环境，界面明确显示“需要重新打开 AI/终端”。不把仅在 App 子进程额外注入 PATH 后成功当作全部外部程序已生效，不自动关闭或重启用户 AI。

### Scenario: 调用入口与重启提示符合实际

在 PATH 最初缺失、App 运行期间被修改、同名命令冲突、路径含空格/中文，以及 macOS GUI 与 shell PATH 不同的情况下，能区分独立 CLI 本身可用与外部命令可达。接入指向被验证的独立入口，旧进程环境需要重启时明确提示，用户其他 PATH 项和命令不受覆盖。

## 6. AI 接入文件

首版入口为 Codex 与 Claude Code，检测已安装本体而不代装或登录。仅操作用户勾选的目标和当前用户作用域，写到目标支持的技能目录；尊重可识别的自定义用户根目录，旧路径/重复同名技能可见，不静默迁移删除。其余已有技能安装目标继续保留原功能。

Codex 默认个人目录为 `~/.agents/skills/smart-search-cli`，Claude Code 为 `~/.claude/skills/smart-search-cli`。Codex 历史 `.codex/skills` 副本要报告，不能把历史路径的字节一致当作当前目标已发现。技能内容更新可能被客户端自动发现；涉及新目录、调用入口或未发现更新时给出准确的重新打开提示，不一律把文件变化说成必须重启。

新增接入文件后校验内容和引用完整性。已有文件与安装源相同则不改；已有不同内容不能仅凭“不一致”就称其损坏或过期，也不能静默覆盖。界面提供保留和明确替换的选择；替换前保留可恢复副本，不删除额外用户文件。接入说明明确使用已配置的独立 CLI 与正确配置目录。

### Scenario: 只配置所选 AI 且保留个人内容

在接入缺失、完全一致、自定义修改、额外文件、自定义根目录和历史重复目录的隔离样例中，检测与写入目标正确。未选 AI 不被修改；自定义内容未经明确替换不被覆盖，选择替换有可恢复副本；接入引用的命令/路径在准备环境中实际有效。

## 7. 分层可用性验证

“验证可用性”验证运行环境、独立 CLI 的真实启动和版本、接入文件及本地配置就绪程度。没有 Key 时应明确“CLI 可运行，搜索服务尚未配置”，避免要求重新装环境。仅执行不会调用搜索服务商或自动修复安装的本地检查，验证结果带时间并与当前配置、路径和版本对应。

界面分开呈现“环境已准备好”“CLI 可运行”“接入文件就绪”“需要重启 AI”“AI 内调用待验证”。提供可以复制到所选 AI 的测试指引及预期结果；首版不自动启动付费 AI 会话，也不把用户手动确认或无来源的普通 CLI 活动冒充程序已验证的 AI 调用。

### Scenario: 就绪状态不夸大验证范围

覆盖环境正常但 Key 缺失、CLI 版本读回错误、技能文件就绪但 AI 不存在、AI 未重启、AI 尚未实际调用等情况；每层状态独立且解释清楚。验证不发收费请求，不修改配置，不因 App 内置搜索成功显示目标 AI 已验证。

## 8. 原生操作体验

Windows 与 macOS 沿用原生控件与现有布局、异步操作反馈。主区域以步骤和结果组织，不要求用户理解 Node、npm、Python、PATH 或 mise；技术详情可展开。主要操作为检测、补齐缺项和验证，安装前显示具体计划与作用范围。

首次点击即忙碌，禁止同一次安装重复提交；切页、刷新或重建控件不丢失当前进度。下载、安装和验证的受理不是成功终态。安装写入期间防止 App 升级、后端重连或退出造成不安全中断；可安全取消时解释正在取消直到真实终态。失败和连接丢失后提供准确恢复指引。

### Scenario: 两端反馈持续且避免冲突操作

慢速安装期间连点只触发一次操作，切页返回仍显示实际阶段；失败、断开和重试状态真实。用户不能在写入期间误触另一 CLI 安装/更新或 App 安装；窄窗与键盘操作可访问主要按钮，状态同时有文字而非只用颜色。

## 9. 配置和现有功能

App 仍可独立使用内置后端，独立 CLI 使用既有配置规则；默认目录共享与环境变量/显式目录覆盖的差异必须如实反映。环境准备不修改搜索 Key、服务商顺序、健康记录或用户结果，不把 App 当前会话草稿自动保存到 CLI。

已有搜索、活动、技能安装、App 下载更新和独立 CLI 更新保持功能。本轮不改变公开 CLI 的搜索语义；如为环境安装增加显式 Python 选择能力，应保持普通 npm 安装兼容并覆盖实际调用路径。

### Scenario: 准备环境不改变配置及原功能

安装和验证前后共享配置、草稿、真实/合成密钥和其他服务商设置不被改写；App 内置功能及独立 CLI 既有入口回归通过。显式配置目录与默认目录不同会得到准确提示，而非误称已同步。

## 10. 交付与证据

提供共享后端的分支测试和隔离真实 npm 安装检查，Windows 原生构建与关键交互检查，以及现有 macOS 构建/模型验证入口。运行环境下载来源、最终版本与产物可追溯；构建、模拟协议、真实本机安装、实际 AI 调用分开记录。

支持范围沿用现有 Windows x64/ARM64 和 macOS Intel/Apple Silicon。无法在当前宿主执行的平台或架构明确列为待验；CI 成功不能替代对应干净机器 GUI/安装验收。不因测试而覆盖用户正式安装或同步真实 AI 技能目录。

### Scenario: 验证结果可追溯且平台边界准确

最终候选包含上述关键分支的可运行测试、实际执行结果和构建对应关系；另有新的只读 Verifier 判断全部场景。未执行的 Mac/ARM64 原生安装与真实 AI 调用明确列为未验，不以 Windows 或替身结果宣布全部平台通过；交付前用户原安装和配置保留。

## 11. 面向新用户的 README

英文 `README.md` 与中文 `README.zh-CN.md` 使用相同的入门结构，并在顶部互相链接。正文围绕五个问题：Smart Search 是什么、适合哪些事情、何时需要联网查来源、怎样在 App 完成配置、平时怎样在 App 或 AI 中使用。完整命令表、环境变量表、架构、发布流程和长 JSON 示例从首页迁入手册。首页保留清楚的下载、完整指南、反馈与许可入口，不把读者引入无关的内部开发流程。

介绍以已存在的能力为依据。示例可包括查新的 API 文档、追踪当前信息、读取给定网页、寻找说法出处和比较多份资料。解释联网检索在这些任务中的价值，以及本工具如何统一配置服务和让 AI 调用；不声称本工具适用于每个人、不宣称检索结果必然真实，不添加没有证据的速度/准确率比较。

App 入门按下载打开、按用途补齐服务商配置、显式测试并保存、准备所选 AI 接入、执行一次测试来讲解。最低配置仍为现有主搜索、文档检索和网页读取三类能力，不能为了短而误写成任意一个 Key 就能完成全部功能。普通用户无需学习 CLI 才能跟随主流程；命令行用户有明确的手册入口。

中文文稿按照用户指定的 lieflat-less-ai-tone 清理明确命中的语言问题。章节重组和精简来自用户本轮单独授权；保留下来的事实、限制、来源和数字不能因去 AI 味而变更。该 Skill 不用于改写代码块、第三方引文或英文段落。

### Scenario: README 能让新用户找到并完成第一步

两种语言的 README 都能在首页直接回答用途、场景、下载配置和日常使用问题，主要配置流程不要求输入命令；技术长表和长 JSON 已迁出。中英入口互通，下载与手册链接可用；最低配置、费用触发和证据边界准确，不把开发分支功能误标为已发布稳定包能力。中文成稿已按指定规则复核。

## 12. 单一入口的完整双语手册

用户文档以 `docs/guide` 为唯一手册入口，提供中英文导航与对应页面。组织为 App 入门、完整 CLI 参考、服务商/配置、研究与路由、排障以及开发说明。每个页面能返回手册目录并切换到对应语言。当前实现是命令、参数、配置键和默认值的核对依据，不仅搬运旧 README。

CLI 参考包含当前全部公开命令、别名、子命令、参数、输入输出选择、常见示例和退出/失败语义。配置指南覆盖所有公开受支持的键、用途、必要条件、默认值和优先级，说明 Key 申请入口与测试是否会联网。保留研究的离线/在线区别、同能力回退、已读正文与候选来源的区别、实验性 provider、旧路径兼容、健康冷却及恢复方式。有效信息从 README 迁移，不能静默丢失；过期“最新版本”和历史发布步骤按当前状态纠正或放入明确的历史资料。

移动文档前先查入站链接，当前消费者在同一批更新并检查；旧文档位置可保留简短的导航页以兼容原链接。原历史记录不迁移改写。仓库、npm 展示页、源码分发和打包后的 Skill 都应能找到适用指南，不能只在本机路径上可用。公共 Skill 与 Python 包内副本继续保持一致。文档集中不新建网站或 Wiki，也不增加同步两份完整手册的发布流程。

### Scenario: 手册完整且迁移不造成断链或信息遗漏

来源覆盖表中的有效技术信息在双语手册中都有明确去处；全部公开 CLI 命令/参数和配置键与当前实现对应，中英主题和限制等价。检查 README、现有文档、Skill 及包元数据引用后没有新增本地断链，npm/分发入口使用可解析的手册链接。旧版本说明不再误标最新，未发布功能有清楚边界。

## 13. 语言范围与内容边界

产品提供 `auto`、简体中文和 English。App 的导航、页面标题、按钮、表单说明、占位文字、可访问性标签、确认框、忙碌/空状态、安装/更新反馈、活动状态、错误及恢复指引使用所选语言。共享后端发出的配置说明、命令说明和步骤提示也要覆盖，不能只翻译原生窗口的静态按钮。

CLI 的总帮助、子命令帮助、参数错误、交互式 setup/config 提示、安装与诊断说明、退出前错误和面向人的 Markdown/content 报告使用所选语言。JSON 中由本工具生成且供人阅读的说明可本地化，但键名、枚举、状态码和其他机器标识保持不变。第三方原始错误/安装日志保持原文并用所选语言解释上下文，不承诺翻译外部软件的输出。

命令名、别名、参数名、配置键、服务商 ID、模型 ID、协议方法/事件、JSON 字段/枚举、URL、用户输入、查询和搜索原文不翻译。切换 UI 语言不要求模型重写答案，不改变搜索语言、路由、provider 顺序或网络调用。历史活动与已完成输出不因切换语言被改写。

当前 `utils.fetch_prompt` 的强制中文声明改为保留页面原语言，避免网页抓取改变原文语言；保留其余抓取和结构要求。该修正落实原文保留合同，不增加独立的答案翻译功能。

### Scenario: 中英文覆盖本工具文案且保留用户和机器内容

中文和英文状态下，主要流程以及失败/恢复路径都使用对应语言，后端生成的文字与界面语言一致。静态检查或覆盖清单能识别遗漏的产品字符串。对相同固定输入和模拟服务响应，机器字段、枚举、命令、配置键、用户文本和搜索正文保持一致；抓取提示不再强制中文，而是要求保留页面原语言。第三方原始日志允许保留原文并能被辨识。

## 14. 语言选择与保存

没有显式偏好时，中文系统语言选择简体中文，其他系统语言选择英文；无可用系统语言信息也回退英文。命令行遵循自身 locale 环境，图形 App 使用图形会话的系统语言，不能依赖交互 shell 的语言设置。只改变 Smart Search，不改操作系统 locale 或第三方 AI 的界面语言。

App 设置页提供自动/简体中文/English，并分别以本语言显示名称，切换后的选择跨重启保留。CLI 使用现有配置入口保存语言偏好，并提供全局 `--lang auto|zh|en`；`zh-CN` 等已有兼容语言形式需要正常归一化。优先级为单次参数、专用环境覆盖、当前 CLI 配置中的偏好、系统语言。无效的显式输入给出参数错误和可用取值；损坏或旧配置不能让产品无法启动，应有可理解的回退说明。

App 与独立 CLI 各自保存选择，App 切换不偷偷改变终端偏好；App 给自己的私有后端传递当前界面语言。旧配置缺少语言字段时无需迁移 Key 或重置设置。持久化语言修改使用现有安全配置/设置机制，不写入搜索 Key，不改变当前配置目录或系统 PATH。

### Scenario: 自动语言与显式偏好按约定生效

覆盖中文/英文/其他/未知系统 locale、旧配置缺字段、保存后重启、环境覆盖和单次参数覆盖。App 与 CLI 的选择互不篡改，CLI 单次 `--lang` 不写文件；无效值明确失败或按规定安全回退。语言操作前后 Key、provider 设置、配置目录、PATH 和其他用户数据保持不变。

## 15. CLI 与本地 Web UI 兼容

根命令与各级子命令的帮助在解析阶段就知道所选语言，包括无其他配置的首次 `--help`。`--lang` 在命令前后的支持形式应一致并写入参考；已有 `smart-search ui --lang zh|en` 和可用的 Web UI 双语入口继续兼容，显式 Web UI 参数优先于默认语言，现有本地网页不会因语言扩展失去原功能。

交互式向导的选择项、默认值、确认和错误保持原控制逻辑；语言切换只改变呈现，不改安全输入和密钥掩码。非交互命令可在无 TTY、重定向和脚本/AI 调用时正常使用。JSON 仍为完整可解析的单一输出，翻译提示不得混入 stdout 破坏管道；版本字符串及退出码维持兼容。

### Scenario: CLI 帮助向导和失败输出可以切换且脚本兼容

## 16. 原生 App 切换行为

英文长文案在现有最小窗口宽度可正常换行，主要按钮和焦点可用；不通过缩小到难以阅读的字号掩盖布局问题。日期/时长等展示可按当前语言适当格式化，原数值及存储形式不变。新字符串使用现有简单资源/字典方式组织，不为两种语言引入无关 UI 框架、翻译服务或远程依赖。
