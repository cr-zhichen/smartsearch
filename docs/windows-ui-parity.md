# Windows 界面层级迁移

在 `codex/macos-native-adaptation` 分支上，以 `be622b1` 为迁移起点。迁移 macOS 已确认的信息层级与交互，保留 WinUI 的 NavigationView、列表、开关、Flyout 和 ContentDialog；共用 Python 后端与中英文词库。阶段完成后分别提交推送，整体验收后再创建上游 PR。

## 第一阶段：基础布局、设置与操作提示

- 设置保留单页滚动：顶部项目图标、版本和 GitHub，下面依次为通用、App 更新、独立 CLI 和高级。控件对齐到设置行右侧，CLI 更新、运行环境和内置入口各自有明确边框。
- 操作提示移到固定工具栏入口和 WinUI Flyout，完整文字可选取，长文可滚动，支持关闭后查看和清除；提示不再占据页面布局行。
- 提供共用分栏容器：明确初始／最小／最大栏宽，拖动和方向键调整，按页面保存；窄窗口改为上下组织，不以选中内容的宽度重新测量。滚动位置按页面或 pane key 独立保存。
- 语言切换统一通过 `ApplyState()` 更新快照，覆盖 Skills 状态；工具栏与页面一起刷新。运行环境在设置页也能接收异步状态。
- `mise.toml` 使用本机已安装且符合项目约束的 .NET SDK 8.0.422，新增 Windows 编译、后端依赖与打包任务。

验证：在现有 UTM Windows x64 虚拟机中，用隔离目录 `C:\smartsearch-ui-lab\stage1` 和由 mise 管理的工具链原生编译，最终为 0 警告、0 错误。未新增或运行 UI 单元测试。此阶段为编译验证，尚未声称实机布局验收。

## 第二阶段：服务商与路由

服务商改为独立左右分栏。意图路由是统一列表中的无图标首行；分类、能力和用途说明读取后端 profile。路由模式使用中文标签，提交稳定 ID，只显示当前模式与开关所需的字段。来源、说明和恢复默认值进入字段 Flyout，现有 Key 只作为 PasswordBox 占位掩码。

草稿保存在完整字典中，当前详情的控件只更新自己对应的字段；服务商切换、筛选、路由模式切换不会删除隐藏草稿。保存成功即清理旧编辑器基线；若状态读回失败，保留“已保存”的真实结果并要求刷新，避免已保存内容重新进入草稿。

验证：服务商阶段的最终源码在 UTM Windows x64 原生编译为 0 警告、0 错误。独立只读复核检查了隐藏草稿、中文选项提交、Key 掩码、控件事件与保存流程，发现的保存后刷新失败问题已修复。后续继续做真实页面交互与视觉检查。

## 第三阶段：搜索、活动与 Skills

- 概览先呈现主搜索、文档检索和网页抓取，扩展能力按需展开；配置与回退链详情使用独立弹窗。
- 搜索以左侧请求、右侧结果组织，必填信息保留一级，高级选项单独编辑；关闭与再次打开选项保留输入，结果提供复制、导出和 JSON 详情。
- 活动采用稳定列表与详情分栏，筛选和观察范围分开。选择键包含配置目录和 run ID，异步响应校验选择版本；心跳只更新摘要，不替换正在阅读的详情。观察目录在弹窗内即时增删。
- Skills 将 Agent 选择改为紧凑原生开关列表，文件路径、变更和备份收据放入详情弹窗；运行环境跳转到设置中的独立 CLI 分组。
- 统一限制同一窗口只有一个 ContentDialog，并保留系统键盘与主题语义。新增中文/英文词条完整性检查无缺失。

验证：Windows 原生 x64 目标编译 0 警告、0 错误；完整发布包生成成功，真实 PyInstaller 后端 initialize/shutdown 检查通过。独立源码复核发现的观察目录重绘与活动心跳打断阅读问题已修正。未添加 UI 单元测试。

## Windows 打包兼容

首次建立虚拟环境时先使用 ensurepip。Python 架构依据解释器的 `sysconfig.get_platform()`，避免 Windows on ARM 下的 x64 Python 被宿主机器类型误判。未签名本地预览支持 Windows PowerShell 5.1 的目录复制，签名模块只在显式请求签名时加载；正式签名流程仍使用原有检查。

本机 PyPI 直连失败时，通过已配置的代理在宿主机下载官方 Windows wheels，传入虚拟机离线安装，未关闭 TLS 校验。预览使用独立应用目录和桌面快捷方式；不代表正式安装器或上游发布验收。

## 实际窗口中的排版修正

首个安装预览暴露了滚动内容右移／裁切和系统默认导航阈值不适合本应用的问题。共用滚动容器现在按可视宽度限制正文，并保持左对齐；页面使用统一 24 px 内边距。右侧改用独立的 52 px 工具栏，避免系统 Header 的额外占位，标题、正文和固定底栏统一对齐。

900 px 以上默认展开带文字的主导航。按钮组按真实可用宽度换行；服务商与 Skills 底栏共用边框与布局，Skills 的文件详情与开关回到同一行。主导航底部使用原始透明角色图，不增加图标底板或外框，贴着窗口下沿；收起导航时同时隐藏角色与预留空间。

角色资源 `desktop/windows/Assets/mascot.png` 与 `assets/branding/source.png` 字节一致，不修改原始画稿。

工具栏图标统一 16 px，按钮为 36 px 方形；程序、任务栏和快捷方式使用有背景的完整图标，侧栏角色单独使用透明原图。

最近一轮根据截图统一服务商列表与活动空状态的 24 px 内容边线，普通按钮、下拉和输入框最低高度为 36 px；字段说明使用 14 px 信息符号和无常驻边框的 28 px 按钮。设置分组内标题与说明相隔 4 px，分组与卡片相隔 12 px，模块之间相隔 24 px。

只读详情按钮不再进入异步操作的忙碌状态；其他没有显式操作 ID 的按钮使用独立 ID，避免同文案按钮同时显示处理中。Skills 文件详情按“待安装的文件”和“内容不同的文件”逐行显示，并说明查看不会写入文件。侧栏角色保持水平居中，下移 16 px，由窗口底部自然裁切。
